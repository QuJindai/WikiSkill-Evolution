# WikiSkill-Evolution V0.3 Git Source Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the V0.2 fail-closed `core` target into a governed Git Source Adapter that can patch a pre-registered local Git repository in an isolated worktree, run trusted engineering gates, and accept or roll back the source baseline under the existing strict WikiSkill held-out Gate.

**Architecture:** Add three focused stdlib-only modules: `sources.py` owns trusted source manifests and the authoritative namespaced accepted Git ref, `gates.py` owns a static trusted gate-profile registry and structured results, and `core_adapter.py` owns source-policy validation plus the candidate worktree lifecycle. `assets.CoreDriver` delegates to this adapter while `harness.evolve()` adds an optional pre-gate phase before its existing held-out Gate; Skill/Prompt/Harness drivers keep their current behavior and call compatibility.

**Tech Stack:** Python 3.10+, Python stdlib only, Git CLI subprocesses, pytest, pyflakes, GitHub Actions Python 3.10/3.11/3.12 matrix.

**Spec:** `docs/superpowers/specs/2026-09-01-v0.3-git-source-adapter-design.md`

## Global Constraints

- Proposals are untrusted data and MUST NOT supply repository URLs, shell commands, scripts, environment variables, credentials, gate definitions, signing material, binary payloads, or model weights.
- Source registration is explicit operator action only.
- V0.3 source repositories are already-resolved local Git repositories; the adapter does not clone URLs or fetch remote code.
- `refs/wikiskill/<source_id>/accepted` is the authoritative accepted source SHA after registration; runtime JSON only mirrors this ref.
- Every candidate worktree is created below `<workspace>/runs/core-worktrees/`; proposal data cannot choose its path.
- A core proposal may only `patch` existing tracked UTF-8 text files allowed by the registered manifest.
- `deny` path rules always override `allow` rules.
- Static, Build, and Regression gates are mandatory; Performance may be `not_configured` only when the manifest has `performance: null`.
- Production gate profiles are a static registry in `wikiskill/gates.py`; no runtime/CLI gate registration exists in V0.3.
- No candidate is accepted unless all engineering gates pass and the existing held-out rule is strictly satisfied: `R_candidate > R_best`.
- Rejection or operational failure MUST NOT advance either the accepted source ref or `R_best`.
- Runtime remains stdlib-only; no third-party runtime dependency is added.
- All V0.2 Skill/Prompt/Harness behavior and legacy Skill proposal compatibility remain release gates.

- `wikiskill/core_adapter.py` — exact core proposal schema, Git-tree safety validation, in-memory patch planning, isolated worktree, diff integrity, pre-gate pipeline, accept/reject cleanup.

- [ ] **Step 4: Implement accepted-ref authority and atomic state mirror**

On first registration create `refs/wikiskill/<source_id>/accepted` with `git update-ref <ref> <baseline_sha> <40-zero-old-or-empty-create-semantics>`. If the ref already exists, never reset it from the manifest. `accepted_sha()` reads the Git ref first and repairs mismatching/missing runtime JSON from that ref.

`advance_accepted_sha()` uses compare-and-swap:

```text
git update-ref refs/wikiskill/<source_id>/accepted <new_sha> <expected_old>
```

Then atomically writes runtime JSON through a temp file plus `os.replace`. If state write fails, attempt a compensating CAS from `<new_sha>` back to `<expected_old>` before raising an operational error.

- [ ] **Step 3: Implement exact proposal schema and in-memory patch planning**

Allowed top-level keys are exactly:

```python
{"target", "action", "source_id", "base_sha", "edits"}
```

Require `target="core"`, `action="patch"`, a current accepted `base_sha`, and a non-empty edit list. Allowed edit objects are:

```text
append       -> file, op, content
replace      -> file, op, target, content
insert_after -> file, op, target, content
```

Unknown keys fail closed. Read each base blob with `git show <accepted_sha>:<path>` before creating a worktree. Require tracked regular-file modes `100644` or `100755`, reject mode `120000` symlinks and `160000` gitlinks for the path or any ancestor, reject NUL-containing/non-UTF-8 content, and require `replace`/`insert_after` target occurrence count to equal exactly 1.

Simulate all edits in memory and compute changed-line budget with `difflib.unified_diff`, counting only added/removed content lines (excluding `+++`/`---`). No worktree is created until this plan passes all limits.

- [ ] **Step 6: Implement reject cleanup and accepted commit/ref advancement**

`reject_candidate()` removes only the known generated candidate worktree using `git -C <repo> worktree remove --force <path>` followed by `git worktree prune`; accepted ref/state remain untouched.

`accept_candidate()`:

1. verify candidate integrity again;
2. stage only `session.changed_files`;
3. commit with fixed local identity;
4. resolve candidate HEAD SHA;
5. create temporary reachability ref `refs/wikiskill/<source_id>/candidate-<iteration>`;
6. remove the candidate worktree successfully;
7. CAS-advance `refs/wikiskill/<source_id>/accepted` through `sources.advance_accepted_sha()`;
8. delete the temporary candidate ref;
9. return accepted SHA + cleanup evidence.

If worktree cleanup fails, accepted ref MUST remain unchanged. If accepted-ref CAS fails, classify as operational and leave `R_best` untouched.

- [ ] **Step 3: Extend base driver methods with optional context, no V0.2 behavior changes**

`GitAssetDriver.pre_gates(...)` returns `[]`. Existing Skill/Prompt/Harness implementations ignore `proposal/context` additions. `CoreDriver` stops using the V0.2 placeholder manifest lifecycle and delegates:

```python
def validate(self, ws, proposal):
    core_adapter.validate_core_proposal(ws, proposal)

def prepare(self, ws, iteration, proposal=None):
    if proposal is None:
        raise ValueError("core prepare requires proposal")
    return core_adapter.begin_candidate(ws, iteration, proposal)

def apply(self, ws, proposal, context=None):
    return core_adapter.apply_candidate(context)
```

`pre_gates`, `diff`, `accept`, `rollback` delegate similarly. Keep `core_manifest_path()` available for backward API compatibility, but V0.3 execution no longer treats its V0.2 placeholder JSON as source authority.
