# V0.2 Multi-Asset Evolution

V0.2 generalizes WikiSkill's candidate mutation layer while keeping one evidence and validation loop:

```text
raw traces -> persistent wiki -> target-aware proposal -> Asset Driver
           -> held-out validation -> accept / rollback
```

The gate is unchanged: a candidate is accepted only when `R_val > R_best`. Equality is rejection. Raw traces remain immutable, and the Wiki is never rolled back.

## Asset targets

| Target | Active workspace state | V0.2 behavior |
|---|---|---|
| `skill` | `skills/active/` | Create/patch `SKILL.md` packages; backward compatible with legacy proposals. |
| `prompt` | `assets/prompts/active/inference.txt` | Create/patch the workspace inference overlay without editing package source. |
| `harness` | `assets/harness/active/policy.json` | Create/patch a typed declarative execution policy. |
| `core` | `assets/core/active/manifest.json` | Contract only; mutations fail closed in V0.2. |

A legacy proposal without `target` is normalized to `target="skill"`.

## Harness policy

The only mutable harness keys in V0.2 are:

- `inference_max_turns`: integer `1..500`
- `maintainer_max_turns`: integer `1..500`
- `proposer_max_turns`: integer `1..500`
- `maintainer_run_budget`: integer `1..100000`
- `proposer_run_budget`: integer `1..100000`

Unknown keys, booleans, wrong types, and out-of-range values are rejected before validation runs.

Inference turn precedence is:

```text
explicit CLI --max-turns > active harness policy > V0.1 default 15
```

Maintainer and proposer use their active policy values when present, otherwise the existing defaults (`60/1500` and `60/1800`).

## Safety and rollback

Each mutable target has its own Asset Driver and Git-backed snapshot lifecycle. A rejected candidate rolls back only that asset. The Wiki and raw evidence remain intact.

Drivers fail closed on unknown targets/actions/edit operations, path traversal, absolute paths, symlink escape, and invalid policy values. Harness proposals cannot provide commands, scripts, environment variables, provider credentials, or arbitrary paths.

`core` is deliberately non-executing in V0.2. It cannot edit runtime source, invoke builds, change model weights, or execute an adapter supplied by a proposal.

Invalid proposals are recorded in `wiki/skill-impact.md` with their complete proposal JSON and error, but no held-out validation rollout is performed.

## Proposal examples

Prompt overlay:

```json
{
  "target": "prompt",
  "action": "create",
  "name": "inference",
  "content": "Verify all numeric units before finalizing."
}
```

Harness policy:

```json
{
  "target": "harness",
  "action": "patch",
  "name": "policy",
  "updates": {
    "inference_max_turns": 21,
    "proposer_max_turns": 80
  }
}
```

Core mutations are recognized but rejected as unsupported in this phase.
